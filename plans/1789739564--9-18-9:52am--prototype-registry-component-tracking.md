# Prototype registry component tracking

Question: can a developer or coding agent identify and acknowledge local component changes while preserving the original shadcn installation?

1. Create a public GitHub repository and a feature worktree under ~/code2.
2. Preserve the research and scope this first experiment to file-based installation provenance.
3. Fetch a real shadcn button with a pinned installer, retain the upstream artifact, and install it in a disposable consumer.
4. Implement offline status, diff, check, and customization records against retained installed contents.
5. Exercise unchanged, modified, acknowledged, modified-again, missing-file, and corrupt-baseline cases. Run a real installation demo.
6. Commit and push the prototype branch, with a draft pull request and instructions to reproduce it.

Expected outcome: a runnable CLI and evidence about the provenance model. Updates, upstream contribution submission, MCP, ESLint, and shared CSS ownership remain subsequent experiments. This prototype does not implement the full roadmap.
